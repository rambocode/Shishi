# 1.0.2 检查项编辑、焦点与底部操作栏

日期：2026-09-15。范围包含连续反馈：已有检查项不能修改、聚焦延迟、行尾按钮与底部删除、圆形控件/分隔线细节、编辑行统一底色。

## 根因与修复

1. AppKit表格会为父行doubleAction延迟子文本框获得焦点。对已展开卡片内部可编辑文字控件，在卡片与表格边界显式放行响应者；不改变普通折叠行的行为。
2. 表格doubleAction再次调用编辑入口时，原逻辑重新focusTitle，导致输入改到父标题。同一卡片已展开时不重复聚焦父标题。
3. 检查项使用独立原生field editor，编辑背景与整行共用颜色，避免表格共享编辑器覆盖出白色矩形。
4. 选择在焦点成功或原生编辑开始后更新，不在尚未取得编辑权限前先切换底部删除目标。

## UI与删除边界

- 圆形勾选框缩小并采用较深蓝色；分隔线更细更浅，从行首延伸。
- 选中行使用完整浅灰圆角底色；编辑状态不额外显示白色输入框。
- 行尾只有排序手柄，选中/悬停时显示；没有行尾删除叉。
- 底部操作栏为移动、删除、更多；清单内移动与手柄都只重排当前父待办内的检查项。
- 删除严格按选中检查项ID处理。删除后清空选择并禁用删除按钮，必须重新选中才能继续删，不能连点误删邻项，更不能落入父待办删除路径。
- 清单底部操作被视为卡片编辑的一部分，不因点击底部按钮提前关闭卡片。

- 新增响应者/双击事件回归测试：修复前4个焦点断言失败；补齐父行doubleAction场景后再次出现父标题被误改的失败；最终全部转绿。
- 全量79项测试通过，0失败、0跳过，包含授权Things副本只读兼容校验。
- 实际验收副本中，鼠标修改已有“检查安装包”文字，保存并重启后新文字保留，父标题和清单ID/完成状态不变。
- 最终窗口中连续单击两条检查项切换，焦点分别停留在正确文字控件；真实截图确认统一底色、圆形控件和底部操作。
- 实际点击底部删除仅移除选中检查项，删除按钮立即禁用；Escape取消验收草稿后两条检查项和父待办仍保留。
